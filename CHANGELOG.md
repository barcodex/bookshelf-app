# Changelog

## [Unreleased]

### Фильмы
- Раздел «Фильмы» в меню культурного дневника теперь работает: лента по годам просмотра, добавление, поиск по тексту, рейтингу и тегам, карточка с кнопкой «Открыть в IMDb»
- Карточки хранятся в `movies/<режиссёр>-<название>.md` рядом с `books/`: `title`, `original_title` (если отличается), `director`, `year`, `imdb`, `tags`, `rating` (1–10) или `abandoned: true` («не досмотрено»; оценка и эта отметка взаимоисключающие), `date_watched`; тело — «Резюме» и «Отзыв», как у книг
- В поле IMDb можно вставить ссылку или идентификатор `tt…` — сохраняется каноничная ссылка
- Недосмотренные фильмы остаются в ленте на своей дате с пометкой «не досмотрено»
- Загрузка, кэш и инкрементальное обновление по SHA обобщены для разделов: у книг и фильмов свои кэши, фоновая проверка обновляет оба
- Переводы для всех 6 языков интерфейса
### Исправлено
- Веб: поля «Начало чтения» и «Конец чтения» снова открывают календарь по клику (Chrome, Safari)

### Культурный дневник: меню разделов
- Шапка приложения с названием раздела: нажатие открывает меню «Культурный дневник» с разделами Книги, Фильмы, Сериалы, Выставки, Концерты
- Пока работают только книги, остальные разделы помечены «скоро» и неактивны
- У каждого раздела свой цвет и иконка на цветной плитке (хлопушка, экран с эпизодами, портик музея, микрофон)
- Новый favicon: цветок, по лепестку на каждый раздел
- Переводы для всех 6 языков интерфейса

## [0.5.0] — 2026-10-23

### Брошенные книги
- Новые поля карточки: `date_abandoned` (вместо `date_finished`) и необязательное `abandoned_at` — где бросил, например `30%`
- Брошенные книги исключены из таймлайна, «Сейчас читаю» и поиска
- Секция «Брошенные» в самом низу таймлайна, свёрнута по умолчанию: компактный список с названием, автором, датой и местом, где бросил
- Кнопка «Бросить чтение» в карточке книги, которую сейчас читаю: попап с подтверждением, местом, где бросил, и отзывом
- Кнопка «Снова начать читать» у брошенной книги: возвращает её в «Сейчас читаю», ставит дату начала, если её не было
- Исправлено: при пустом «Резюме» раздел «Отзыв» дублировался после сохранения
- Переводы для всех 6 языков интерфейса

## [0.4.0] — 2026-07-30

### Три секции таймлайна
- Секция «Сейчас читаю» — книги с `date_started` без `date_finished`, отображаются первыми
- Секция «Прочитал раньше» — книги без обеих дат, в алфавитном порядке по автору
- Фоновая проверка SHA на каждый фокус вкладки Timeline и Search
- Инкрементальное обновление кэша: загружаются только изменённые файлы
- Проверка SHA не запускается на вкладках «Добавить книгу» и «Настройки»

## [0.3.0] — 2026-06-29

### i18n, тема и деплой
- Локализация на 6 языков: русский, английский, немецкий, французский, испанский, итальянский
- Экран выбора языка при первом запуске
- Тёплая бумажная тема для веба (`warm paper`), адаптивные цвета для нативных платформ
- Рендеринг `summary` и `review` как Markdown в карточке книги
- Иконки типа носителя (бумажная, аудио, электронная)
- Кликабельные теги — переход на поиск с предустановленным фильтром
- GitHub Actions: автодеплой на Vercel при пуше в `main`
- Деплой: https://bookshelf-app-xi.vercel.app

## [0.2.0] — 2026-06-01

### Надёжность и производительность
- Compare API для батчевой загрузки: только изменённые файлы при обновлении
- Миграция кэша с `localStorage` на `IndexedDB`
- Таргетированное обновление книги в кэше при сохранении (без полной перезагрузки)
- Обработка ошибок GitHub API с отображением в UI

## [0.1.0] — 2026-05-29

### Первый релиз
- Таймлайн книг, сгруппированный по годам, с градиентными заголовками секций
- Статистика носителей и количество книг в заголовке каждого года
- Поиск с дебаунсом, фильтрами по медиа и тегам
- Поля `tags`, `rating`, `media` в форме добавления книги
- Кэш на основе SHA последнего коммита, опрос при каждом открытии
- Экран настроек: GitHub PAT и репозиторий
- Onboarding: экраны объяснения работы с приватным репозиторием

## Roadmap

### Публикация в WordPress
Возможность публиковать отзывы из карточек bookshelf в блог `knigoschet.wordpress.com` — в обратную сторону от текущего импорта постов в карточки. WordPress.com поддерживает REST API с аутентификацией через Application Password (аналогично GitHub PAT). Реализация: кнопка «Опубликовать в блог» в карточке книги, которая берёт `review`, форматирует как пост и отправляет через API.
