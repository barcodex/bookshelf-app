# Changelog

## [Unreleased]

### Обмен карточками
- «Ещё → Обмен карточками → Экспорт»: выбор карточек по разделу, году и тегу, файл `culture-diary-ГГГГ-ММ-ДД.json` скачивается в браузере (на телефоне уходит через системное «Поделиться»)
- В файл попадают описание и Резюме; оценка и Отзыв не попадают никогда, у книг отрезаются `media`, `source` и даты чтения, у фильмов дата и место просмотра и «не досмотрено». Формат описан в `docs/export-format.md`
- «Импорт» читает файл (в браузере выбором файла, везде вставкой текста), ищет совпадения со своими карточками по имени файла и ключевым полям (автор и название, IMDb или название и год, артист и дата, название и дата) и для каждого совпадения предлагает «Пропустить», «Дополнить» (только пустые поля) или «Заменить»; теги объединяются, своя оценка, отзыв и даты не трогаются
- Все карточки импорта записываются одним коммитом через Git Data API

### Театр, выставки, лекции, стендап
- Новый раздел «Театр» со своим лепестком (охра, театральная маска): мюзиклы, спектакли, опера и балет. Карточки в `theatre/<название>-<дата>.md`: `title`, `original_title` (если отличается), `kind` (`musical`, `play`, `opera`, `ballet`), `author`, `company` (труппа, театр или тур), `venue`, `link`, `tags`, `rating`, `date_attended`
- Раздел «Выставки» заработал: `exhibitions/<название>-<дата>.md` с теми же полями, кроме `original_title`, `company` и `kind`; автор подписан «Художник»
- Новый раздел «Лекции» со своим лепестком (бирюзовый, доска для презентации): `lectures/<название>-<дата>.md`, поля как у выставок, автор подписан «Лектор»
- Стендап живёт в «Концертах»: переключатель «Концерт / Стендап» в форме, во фронтматтере `kind: standup` (у обычного концерта поля нет, старые карточки не меняются), в ленте подпись «Стендап», поиск находит по слову «стендап»
- В заголовке года счёт по видам, заготовка для итогов года: «Мюзиклы: 2 · Спектакли: 1», «Концертов: 9 · стендап: 2»
- Театр, выставки и лекции собраны на общих компонентах (`EventForm`, `EventRow`, `EventDetailModal`, экраны `Events*`), разделы отличаются только настройками в `src/utils/eventSections.ts`; у каждого свой кэш и фоновая проверка обновлений
- Фавикон-цветок теперь с семью лепестками
- Переводы для всех 6 языков интерфейса
- Имя файла из латиницы с диакритикой теперь читается: «Les Misérables» → `les-miserables`, «Zürich» → `zurich` (раньше буква превращалась в дефис: `les-mis-rables`)

### Концерты
- Раздел «Концерты» в меню культурного дневника теперь работает: лента по годам, добавление, поиск по артисту, разогреву, площадке, рейтингу и тегам, карточка с кнопкой «Открыть в Spotify»
- Карточки хранятся в `concerts/<артист>-<дата>.md`: `artist`, `support` (разогрев через запятую, групп может быть несколько), `venue` (площадка и город), `spotify`, `tags`, `rating` (1–10), `date_attended`; тело — «Резюме» и «Отзыв», как у книг и фильмов
- В поле Spotify можно вставить ссылку из приложения (с `?si=…`, `/intl-xx/`) или `spotify:artist:…` — сохраняется каноничная ссылка на артиста
- Разогрев вводится чипами, как теги, но без перевода в нижний регистр
- Свой кэш и фоновая проверка обновлений для концертов
- Переводы для всех 6 языков интерфейса

### Таблицы в карточках
- В «Резюме» и «Отзыве» отображаются Markdown-таблицы (например, «Что здесь наука, что — выдумка»): заголовок, рамки, жирный текст в ячейках, выравнивание через `:---:`
- Ширина колонок подбирается по длине текста; на узком экране таблица прокручивается вбок, а не сжимается
- Без новых зависимостей: таблица собрана из обычных `View`/`Text`, поэтому работает одинаково в вебе, на iOS и Android

### Фильмы
- Раздел «Фильмы» в меню культурного дневника теперь работает: лента по годам просмотра, добавление, поиск по тексту, рейтингу и тегам, карточка с кнопкой «Открыть в IMDb»
- Карточки хранятся в `movies/<режиссёр>-<название>.md` рядом с `books/`: `title`, `original_title` (если отличается), `director`, `year`, `imdb`, `tags`, `rating` (1–10) или `abandoned: true` («не досмотрено»; оценка и эта отметка взаимоисключающие), `date_watched`; тело — «Резюме» и «Отзыв», как у книг
- В поле IMDb можно вставить ссылку или идентификатор `tt…` — сохраняется каноничная ссылка
- Недосмотренные фильмы остаются в ленте на своей дате с пометкой «не досмотрено»
- Загрузка, кэш и инкрементальное обновление по SHA обобщены для разделов: у книг и фильмов свои кэши, фоновая проверка обновляет оба
- Переводы для всех 6 языков интерфейса
### Исправлено
- Веб: поля «Начало чтения» и «Конец чтения» снова открывают календарь по клику (Chrome, Safari)

### Культурный дневник: меню разделов
- Шапка приложения с названием раздела: нажатие открывает меню «Культурный дневник» с разделами Книги, Фильмы, Сериалы, Выставки, Концерты
- Пока работают только книги, остальные разделы помечены «скоро» и неактивны
- У каждого раздела свой цвет и иконка на цветной плитке (хлопушка, экран с эпизодами, портик музея, микрофон)
- Новый favicon: цветок, по лепестку на каждый раздел
- Переводы для всех 6 языков интерфейса

## [0.5.0] — 2026-10-23

### Брошенные книги
- Новые поля карточки: `date_abandoned` (вместо `date_finished`) и необязательное `abandoned_at` — где бросил, например `30%`

- Секция «Брошенные» в самом низу таймлайна, свёрнута по умолчанию: компактный список с названием, автором, датой и местом, где бросил
- Кнопка «Бросить чтение» в карточке книги, которую сейчас читаю: попап с подтверждением, местом, где бросил, и отзывом
- Кнопка «Снова начать читать» у брошенной книги: возвращает её в «Сейчас читаю», ставит дату начала, если её не было
- Исправлено: при пустом «Резюме» раздел «Отзыв» дублировался после сохранения
- Переводы для всех 6 языков интерфейса

## [0.4.0] — 2026-07-30

### Три секции таймлайна
- Секция «Сейчас читаю» — книги с `date_started` без `date_finished`, отображаются первыми
- Секция «Прочитал раньше» — книги без обеих дат, в алфавитном порядке по автору
- Фоновая проверка SHA на каждый фокус вкладки Timeline и Search

- Проверка SHA не запускается на вкладках «Добавить книгу» и «Настройки»

## Roadmap

### Публикация в WordPress
Возможность публиковать отзывы из карточек bookshelf в блог `knigoschet.wordpress.com` — в обратную сторону от текущего импорта постов в карточки. WordPress.com поддерживает REST API с аутентификацией через Application Password (аналогично GitHub PAT). Реализация: кнопка «Опубликовать в блог» в карточке книги, которая берёт `review`, форматирует как пост и отправляет через API.
